# Windows 长录音自动切割工具

一个给 Windows 用户使用的长录音切割小工具。它可以把 `mp3`、`m4a`、`wav`、`aac`、`flac` 音频文件自动切成多个片段，每段最长 2 小时。

这个项目用 Python 编写，实际切割由 FFmpeg 完成。默认使用 FFmpeg 的 `segment` 功能和复制模式，不重新编码，所以速度通常很快。

## 功能特点

- 支持 `mp3`、`m4a`、`wav`、`aac`、`flac`
- 每 7200 秒自动切一段，也就是每段最长 2 小时
- 输出文件夹自动创建在原音频旁边
- 输出文件名格式为 `原文件名_part_001.mp3`、`原文件名_part_002.mp3`
- 优先不重新编码，速度快，尽量保持原音频质量
- 支持中文路径和中文文件名
- 出错时显示尽量容易理解的中文提示
- 不需要打开复杂软件，双击 `run.bat` 即可使用

## 适合谁使用

- 需要把会议录音、课程录音、采访录音切成较短片段的人
- 需要上传长录音，但平台限制单个文件时长或大小的人
- 不想学习 FFmpeg 命令，只想拖入文件自动处理的人
- Windows 用户，尤其是完全不懂编程的用户

## 安装 Python

这个工具需要 Python 3。

1. 打开 Python 官方下载页面：<https://www.python.org/downloads/windows/>
2. 下载适合 Windows 的 Python 3 安装包。
3. 运行安装包。
4. 如果安装界面有 `Add python.exe to PATH` 选项，请勾选它。
5. 安装完成后，关闭并重新打开命令行窗口，或直接重新双击 `run.bat`。

如果双击 `run.bat` 后提示找不到 Python，通常是 Python 没有安装，或者安装时没有加入 PATH。

## 安装 FFmpeg

这个项目不包含 `ffmpeg.exe`。你需要自己安装 FFmpeg。

推荐方式：

1. 打开 Windows 终端、PowerShell 或命令提示符。
2. 输入下面的命令并按 Enter：

```bat
winget install Gyan.FFmpeg
```

3. 安装完成后，关闭窗口，再重新打开。
4. 输入下面的命令测试：

```bat
ffmpeg -version
```

如果能看到版本信息，说明 FFmpeg 安装成功。

也可以从 FFmpeg 官方下载页面查找 Windows 版本：<https://ffmpeg.org/download.html>

## 使用方法

1. 下载本项目代码。
2. 解压到一个普通文件夹，例如桌面或下载目录。
3. 双击 `run.bat`。
4. 把音频文件拖到打开的黑色窗口里，或者粘贴音频文件的完整路径。
5. 按 Enter。
6. 等待切割完成。

切割完成后，会在原音频旁边生成一个新文件夹，例如：

```text
我的录音.mp3
我的录音_split/
  我的录音_part_001.mp3
  我的录音_part_002.mp3
```

如果同名输出文件夹已经存在，程序会自动创建类似 `我的录音_split_02` 的新文件夹，避免覆盖旧结果。

## 常见问题

### 双击后提示找不到 Python

请先安装 Python 3。安装时尽量勾选 `Add python.exe to PATH`。

### 提示没有找到 FFmpeg

说明系统里还不能直接运行 `ffmpeg`。请按上面的“安装 FFmpeg”说明安装，然后重新打开窗口再试。

### 为什么切割速度很快？

因为默认使用 `-c:a copy`，也就是复制音频流，不重新编码。

### 会不会改变音质？

正常情况下不会重新编码，所以不会因为重新编码造成音质损失。

### 为什么有些文件切割失败？

少数音频文件可能时间戳异常、格式损坏，或者不支持直接复制切割。可以先用音频转换工具把它转换成常见格式，例如 `mp3` 或 `wav`，再运行本工具。

### 可以一次拖入多个文件吗？

目前一次只处理一个音频文件。

### 可以改成每 1 小时切一段吗？

可以。打开 `split_audio.py`，把这一行：

```python
SEGMENT_SECONDS = 7200
```

改成：

```python
SEGMENT_SECONDS = 3600
```

保存后重新运行即可。

### 支持视频文件吗？

不推荐。这个工具面向音频文件，只会处理第一个音频流。

## 注意事项

- 请不要把 `ffmpeg.exe` 上传到这个项目里。
- 切割结果会占用额外磁盘空间，请先确认磁盘空间足够。
- 如果原音频正在被播放器、剪辑软件或网盘同步软件占用，可能会失败。
- 复制模式速度快，但对少数异常文件不如重新编码稳定。
- 文件名和路径可以包含中文。
- 测试音频和切割输出文件夹不应该上传到 GitHub。
